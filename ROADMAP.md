## P0 — безопасность автопубликации

### Проверка фактов

- [x] Каждый факт должен иметь подтверждающий источник.
- [x] Числа, даты, адреса и имена должны проверяться отдельно.
- [x] Запрещать LLM добавлять сведения, отсутствующие в источниках.
- [x] При противоречии между источниками не публиковать пост автоматически.
- [x] Указывать противоречивую информацию как неподтверждённую либо отправлять на проверку.
- [x] Для обычных новостей требовать два независимых источника.
- [x] Для новостей ведомств разрешить один официальный первоисточник.

### Риск-фильтр

- [x] Выделить категории повышенного риска: преступления, смерти, аварии, обвинения,
  пропавшие люди, чрезвычайные ситуации.
- [x] Не публиковать неподтверждённые обвинения.
- [x] Не раскрывать чувствительные персональные данные.
- [x] Для опасных категорий требовать официальный источник.
- [x] Отправлять сомнительные материалы в очередь ручной проверки.
- [x] Хранить причину, по которой публикация была заблокирована.

### Защита от галлюцинаций LLM

- [x] Использовать строгий структурированный JSON-ответ.
- [x] Проверять ответ через Pydantic.
- [x] Не принимать неизвестные поля.
- [x] Ограничить длину заголовка и текста.
- [x] Проверять ссылки на принадлежность разрешённым доменам.
- [x] Не давать LLM самостоятельно создавать ссылки.
- [x] Сохранять исходные материалы и результат модели для аудита.

## Проверка перед включением автоматики

### Этап 1 — локальный dry-run

- [ ] Все тесты проходят.
- [ ] Ruff и Mypy проходят.
- [ ] Все источники проходят `sources-check`.
- [ ] Обработано минимум 100 реальных материалов.
- [ ] Нет необработанных исключений.

### Этап 2 — теневой режим на 3–7 дней

- [ ] Бот работает по настоящему расписанию.
- [ ] Посты сохраняются, но не публикуются.
- [ ] Вручную проверено 100–200 черновиков.
- [ ] Нет выдуманных фактов.
- [ ] Нет неправильных объединений критических событий.
- [ ] Нет систематических пропусков новостей.
- [ ] Рассчитана стоимость LLM на день и месяц.

### Этап 3 — тестовые каналы

- [ ] Включена публикация в закрытые Telegram- и MAX-каналы.
- [ ] Проверены редактирование и обновления.
- [ ] Проверено восстановление после падения.
- [ ] Проверены дубликаты и `UNCERTAIN`.
- [ ] Бот стабильно работает минимум 7 дней.

### Этап 4 — ограниченный production

- [ ] Публикуются только низкорисковые категории.
- [ ] Рискованные новости проходят ручное подтверждение.
- [ ] Есть kill switch.
- [ ] Настроены уведомления об ошибках.
- [ ] Назначен человек, проверяющий жалобы и исправления.

### Этап 5 — полная автоматизация

- [ ] Все источники автоматически контролируются.
- [ ] Сломанные источники автоматически отключаются.
- [ ] `UNCERTAIN` разрешается автоматически.
- [ ] Повторные публикации исключены.
- [ ] Высокорисковые новости проходят усиленную проверку.
- [ ] Ошибочные посты можно быстро исправить или удалить.
- [ ] Работают резервное копирование и восстановление.
- [ ] Система стабильно проработала минимум 14 дней.
- [ ] Ручная проверка показывает приемлемое качество.

Главный критерий полной готовности: NewsBot должен безопасно переживать поломку
источника, ошибку LLM, недоступность Telegram или MAX, перезапуск сервера и
повторный запуск цикла — без выдуманных фактов и дублирующихся постов.
